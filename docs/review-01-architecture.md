The dynamic AST is a sensible starting point. I would keep it, but fix the semantic gaps below and make inheritance dispatch explicit before scaling out dialect work.

1. **Eq/Hash currently differs from Python in observable ways.** Python treats `Select()` and `Select(expressions=[])` as equal: an empty list contributes nothing to its hash. MoonBit counts the argument and hashes its key/list length. Python also equates a scalar argument with a singleton list containing that value. See [MoonBit equality/hash](../src/core/expr.mbt:1440) versus [Python hashing](https://github.com/tobymao/sqlglot/blob/main/sqlglot/expressions/core.py:866). Define a shared normalized argument stream for equality and hashing. Keep collision-safe structural equality; reproducing Python’s accidental hash-collision equality is unnecessary.

2. **Mutation/traversal is mostly faithful, with specific gaps.**
   - [`set_at`](../src/core/expr.mbt:901) rejects negative indices; Python accepts them. Preserve Python’s actual pop/slice behavior for list replacement—simply normalizing every negative index gives different results.
   - [`copy()`](../src/core/expr.mbt:732) shallow-copies metadata values; [Python deep-copies metadata](https://github.com/tobymao/sqlglot/blob/main/sqlglot/expressions/core.py:1013). Lists such as `meta["dot_parts"]` and node-valued metadata will remain shared.
   - [`dfs`/`bfs`](../src/core/expr.mbt:980) correctly delay pruning and child expansion until the next iteration. [`transform`](../src/core/expr.mbt:1251) correctly captures the old parent position and uses physical identity. `replace`, self-replacement, parent-replacement guards, and scalar-child-to-list promotion also look faithful within their narrower signatures. Do not “fix” stale parent pointers left by ordinary `set`: Python leaves those too.

3. **`DateTrunc` normalizes too late; `TimeUnit`’s surprising casing is correct.** [`Expr::new`](../src/core/expr.mbt:130) attaches the original unit before `post_init` replaces it. Python’s [DateTrunc constructor](https://github.com/tobymao/sqlglot/blob/main/sqlglot/expressions/temporal.py:168) replaces it before establishing parents. Consequently, your discarded unit incorrectly acquires a parent, potentially corrupting an existing tree if reused. Normalize DateTrunc’s constructor arguments first. Conversely, preserve TimeUnit’s abbreviation-before-uppercase order: Python produces `Q` from lowercase `q`, but `QUARTER` from uppercase `Q`; DateTrunc produces `QUARTER` from both.

4. **Tokenizer parity needs Unicode and EOF fixes.** [`nul`](../src/core/tokens.mbt:323) conflates a real U+0000 with Python’s empty-string sentinel. For example, Python tokenizes `a\0b` as one VAR; [`scan_var`](../src/core/tokens.mbt:959) splits it. Use bounds/EOF state or `Char?`. The [Unicode helpers](../src/core/helper.mbt:24) are approximations: Python equates `Var("İ")` with `Var("i\u0307")`, whereas your lowercase conversion does not. [`is_valid_int`](../src/core/tokens.mbt:798) also rejects Unicode decimal digits accepted by Python—for example PostgreSQL `B'١'`. Generate Unicode property/case tables, including expanding/contextual mappings. `Array[Char]` itself is a reasonable way to retain Python code-point offsets.

5. **Use resolved virtual tables plus explicit implementation entry points.** A hook per genuinely overridden method is workable, but “call base for `super()`” must mean the next implementation after the *defining class*, using the actual Parser/Generator MRO.
   - [Redshift’s `datatype_sql`](https://github.com/tobymao/sqlglot/blob/main/sqlglot/generators/redshift.py:335) must call Postgres, then Generator.
   - [Spark2 explicitly skips Hive](https://github.com/tobymao/sqlglot/blob/main/sqlglot/generators/spark2.py:245) with `super(HiveGenerator, self)`.
   
   Generate resolved owner metadata and expose named implementation functions. Those implementations must retain the original receiver, so their internal `self.foo()` calls still dispatch to the most-derived override. Never temporarily replace hooks to implement `super`.

   Keep **SQL dispatch and method dispatch separate**: inherited TRANSFORMS beat even descendant methods in [`_build_dispatch`](https://github.com/tobymao/sqlglot/blob/main/sqlglot/generator.py:79), while direct `datatype_sql` calls bypass TRANSFORMS. Preserve exact-kind lookup and Func/Property fallbacks. Typed method slots must cover differing signatures, private helpers, non-`parse_*` methods, and Dialect methods such as [BigQuery normalization](https://github.com/tobymao/sqlglot/blob/main/sqlglot/dialects/bigquery.py:134). Resolve and freeze settings once; mutable optional hooks are useful during construction, not execution.

6. **The proposed package graph has a real cycle unless you invert dependencies.** Base [`generator.toarray_sql`](https://github.com/tobymao/sqlglot/blob/main/sqlglot/generator.py:5231) needs annotation; [parser normalization](https://github.com/tobymao/sqlglot/blob/main/sqlglot/parser.py:4336) and [transforms](https://github.com/tobymao/sqlglot/blob/main/sqlglot/transforms.py:763) also depend on optimizer functionality. Python’s lazy imports do not solve MoonBit package dependencies.

   Initially, keep scope/normalization primitives in core and inject annotation/optimizer-dependent transforms through a small typed services interface. The facade assembles core, optimizer, and dialect implementations. Optimizer consumes dialect settings/hooks without importing concrete dialect packages. Prefer an explicit generated built-in registry in the facade over relying solely on `fn init`; named dialect lookup must have a concrete import path to every registered dialect. Extract cross-dialect helpers into shared support packages when sibling imports would create cycles.

7. **Keep the representation, improve its boundary.** A 1,053-constructor typed AST would impose substantial porting and rewrite overhead. Generated Kind/MRO metadata plus dynamic arguments is a good compatibility layer. Add generated typed accessors/builders and argument validation for ergonomics. [`IntoValue` for arrays](../src/core/expr.mbt:73) silently removes `None` elements; explicitly decide where positional nulls must survive rather than applying this conversion universally.

   Likely performance costs are argument-map allocation/lookups, copied list accessors, and recursive uncached hashing/copying—not the enum. Benchmark those before switching to interned argument keys or arena IDs. Convert deep-tree copy/hash to iterative algorithms; Python already does so. Introduce hash caching only after mutations reliably invalidate ancestors.

For generated dialect settings, derive diffs from **fully initialized** Python classes, preserve sequence/map order, and represent deletions and `None` distinctly. Redshift [removes inherited transforms](https://github.com/tobymao/sqlglot/blob/main/sqlglot/generators/redshift.py:57), and the [Dialect metaclass modifies them too](https://github.com/tobymao/sqlglot/blob/main/sqlglot/dialects/dialect.py:304). Record the upstream commit and validate reconstructed settings against complete snapshots.

Prioritize: expression/token differential tests → a small end-to-end parser/generator slice → inheritance probes across the named chains → scope/type services → broad dialect and optimizer work. Don’t make complete `identity.sql` coverage the prerequisite for learning whether inheritance works.

The fixture extractor should wrap the original Validator and preserve its returned expression. Export options, expected exceptions, warning expectations, and `validate_transpile` too: [Validator](https://github.com/tobymao/sqlglot/blob/main/tests/dialects/test_dialect.py:54) uses `pretty`, `identify`, and differing unsupported levels. Add AST comparisons and flag unexpected `Command` fallback; matching SQL alone can hide two compensating bugs or an opaque passthrough. Parallelize independent dialect families after these contracts stabilize; keep inheritance chains parent-first.
